# 归并排序（Merge Sort）

归并排序使用分治思想：把待排区间分成两半，分别排序，再把两个有序区间合并。与快速排序先划分枢轴不同，归并排序把主要工作放在“左右两边已经排好之后，如何合并”。

本篇介绍数组上的递归二路归并排序，使用 0 起始下标、闭区间和一个由调用者提供的辅助数组。

## 1. 算法思想

一个元素单独就是有序序列。不断把区间分成两半，直到每段至多有一个元素，再逐层合并：

```text
分解：  [4 1 3 2] → [4 1] [3 2] → [4] [1] [3] [2]
合并：  [4] [1] [3] [2] → [1 4] [2 3] → [1 2 3 4]
```

合并有序区间时，只需比较两边当前尚未取出的第一个元素，取较小者放到结果中，再推进相应的指针。因为每边内部已经有序，所以其余元素不会比当前头部更小。

## 2. 手推一次合并

假设左边为 `1 4 7`，右边为 `2 3 8`。i、j 分别指向两边的首元素，k 指向结果的下一个写入位置：

| 当前比较 | 取出哪边 | 结果前缀 |
| --- | --- | --- |
| 1 与 2 | 左边 1 | 1 |
| 4 与 2 | 右边 2 | 1 2 |
| 4 与 3 | 右边 3 | 1 2 3 |
| 4 与 8 | 左边 4 | 1 2 3 4 |
| 7 与 8 | 左边 7 | 1 2 3 4 7 |
| 左边已经取完 | 追加右边剩下的 8 | 1 2 3 4 7 8 |

如果右边先耗尽，则追加左边剩余元素。剩余部分本来就有序，不必再比较两边，但仍要把它写到结果中。

## 3. C 语言实现

先把待合并区间复制到 buffer，再从 buffer 读取、向 array 写入，避免覆盖尚未处理的数据。

```c
/* 合并两个已经有序的闭区间 [low, mid] 和 [mid+1, high]。 */
void Merge(int array[], int buffer[], int low, int mid, int high)
{
    for (int k = low; k <= high; ++k) {
        buffer[k] = array[k];
    }

    int i = low, j = mid + 1, k = low;
    while (i <= mid && j <= high) {
        if (buffer[i] <= buffer[j]) {
            array[k++] = buffer[i++];
        } else {
            array[k++] = buffer[j++];
        }
    }
    while (i <= mid) {
        array[k++] = buffer[i++];
    }
    while (j <= high) {
        array[k++] = buffer[j++];
    }
}

void MergeSort(int array[], int buffer[], int low, int high)
{
    if (low < high) {
        int mid = low + (high - low) / 2;
        MergeSort(array, buffer, low, mid);
        MergeSort(array, buffer, mid + 1, high);
        Merge(array, buffer, low, mid, high);
    }
}
```

### 两个函数各自负责什么

- `MergeSort` 负责递归地排好左右两半。
- `Merge` 只负责合并两个**已经有序**的相邻区间，不会自行排序任意两段输入。

`low < high` 是递归条件，区间至多一个元素时直接返回。mid 采用 `low + (high - low)/2` 计算，再分别处理 `[low, mid]` 和 `[mid+1, high]`。两次递归都返回后，调用的是 **Merge**，不是再调用一个参数不同的 MergeSort。

### 辅助数组由谁管理

array 与 buffer 应是两个不重叠的数组，且都能访问到本次排序所需的最高下标。完整排序 n 个元素时，调用者准备 n 个辅助位置，使用 `MergeSort(array, buffer, 0, n-1)`。

本例在 main 中一次性创建 buffer，所有递归调用共用它：同一时刻按顺序处理各个区间，不需要为每层另建一份长度为 n 的辅助数组。buffer 的初始内容没有要求，因为每次合并前都会先复制对应区间。

示例使用局部数组，生命周期覆盖整个排序调用，无需 malloc 或 free。如果用于规模较大的数据，也可以由调用者在堆上分配辅助数组，检查分配结果，并在排序结束后释放；这不改变归并过程。空输入可传入空区间 `[0, -1]`，不需要创建长度为 0 的数组。

### 合并时的三个边界

1. 只有在 i 未越过 mid、j 未越过 high 时，才能同时比较左右两边。
2. 左半区剩余元素从 `buffer[i]` 复制，右半区剩余元素从 **buffer[j]** 复制，两个下标不能混用。
3. 合并区间是闭区间，high 位置的元素也要处理；所有写入都应落在 `[low, high]` 中。

## 4. 为什么稳定

代码在 `buffer[i] <= buffer[j]` 时先取左边。若两边当前记录的关键字相等，左边记录在原始序列中更靠前，优先取它就能保留原相对次序。

例如合并 `2A 5` 与 `2B 4`，先取 2A，再取 2B，得到 `2A 2B 4 5`。递归的每次合并都遵守这一规则，所以整个排序稳定。若把条件改成严格小于 `<`，相等时优先取右边，就可能变成 `2B 2A 4 5`。

## 5. 时间与空间开销

合并长度为 m 的区间时，每个元素只被复制和写回常数次，时间为 O(m)。各层合并的区间互不重叠，每层总工作量为 O(n)，递归高度为 O(log n)。

| 项目 | 本文实现的开销 |
| --- | --- |
| 最好、平均、最坏时间 | 均为 O(n log n) |
| 共用辅助数组 | O(n) |
| 递归调用栈 | O(log n) |
| 总额外空间 | O(n) |

这里的最好时间也是 O(n log n)，因为实现没有跳过已有序区间的合并步骤；即使原数组有序，也仍会逐层复制与合并。如果加入“左半区最大值不大于右半区最小值时跳过合并”的优化，最好情况就需要重新分析，不能混用两种版本的结论。

与本组其他排序相比，数组归并排序能提供稳定性和 O(n log n) 最坏时间，但要付出线性辅助空间。本篇不是原地归并算法；链表归并、外部归并和迭代版本各有不同的实现与空间分析，不在这里混为一谈。

## 6. 编译与运行

完整程序见 [merge_sort.c](src/sort/merge_sort.c)，main 中同时展示了输入数组和辅助数组的声明。已安装 GCC 时，可在源文件目录运行：

```sh
gcc -std=c11 -Wall -Wextra -pedantic merge_sort.c -o merge_sort
./merge_sort
```

输出：

```text
13 27 38 49 49 65 76 97
```

可以对照合并代码手推两种边界：先耗尽左半区、先耗尽右半区。尤其要检查剩余元素来自哪一边，以及相等关键字优先从哪一边取。
