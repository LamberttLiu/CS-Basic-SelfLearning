# [85] 基数排序（Radix Sort）

前面几篇排序通过比较两个元素的大小来决定位置。基数排序换一个角度：把关键字拆成若干位，按位分配、收集，经过多轮处理得到有序结果。

本篇使用**十进制、低位优先（LSD）**的方法，对非负整数升序排序。代码采用 `unsigned int` 保存关键字，采用 C11。

## 1. “基数”和“位数”是什么意思

十进制每一位有 0—9 共 10 种取值，所以基数 r = 10。若最大值为 105，则需要依次处理个位、十位、百位，共 d = 3 轮。位数不足的数在高位视为补 0，例如 7 可看成 007，但不需要真的转换成字符串。

常见的两种处理方向是：

| 方法 | 从哪里开始 | 如何继续 |
| --- | --- | --- |
| LSD，低位优先 | 最低位 | 每轮稳定地处理一位，逐渐扩大已经有序的低位范围 |
| MSD，高位优先 | 最高位 | 先按高位分组，再在各组内部处理后续位 |

两者的组织方式不同。MSD 不是把 LSD 的每轮顺序简单反过来；高位分组后，需要保留组间次序并在组内继续处理。下面只实现 LSD。

## 2. 分配与收集

对当前位准备编号 0—9 的十个桶：

1. 从前向后读取序列，根据当前位的数字放入对应桶。
2. 桶内保持进入时的顺序。
3. 按桶号从小到大收集，形成下一轮的输入。

以 `53 7 105 23 7 80 12` 为例，第一轮处理个位：

| 桶号 | 按进入顺序保存的元素 |
| --- | --- |
| 0 | 80 |
| 1 | 空 |
| 2 | 12 |
| 3 | 53、23 |
| 4 | 空 |
| 5 | 105 |
| 6 | 空 |
| 7 | 7、7 |
| 8 | 空 |
| 9 | 空 |

按桶号收集得到 `80 12 53 23 105 7 7`。注意桶 3 内仍然是 53 在前、23 在后，本轮只按个位排序，不要求它们按完整数值有序。

三轮结果如下：

| 当前处理的位 | 收集后的序列 |
| --- | --- |
| 个位 | 80 12 53 23 105 7 7 |
| 十位 | 105 7 7 12 23 53 80 |
| 百位 | 7 7 12 23 53 80 105 |

每轮都使用上一轮的结果，不能重新从原数组开始。处理百位时，小于 100 的数都进入桶 0；因为桶内顺序被保留，它们仍按上一轮确定的低两位次序排列。

## 3. 为什么每一轮必须稳定

处理完个位后，序列按个位有序。稳定地处理十位后，十位不同的元素按十位排列；十位相同的元素继续保留上一轮的个位次序，因此低两位整体有序。对后续位重复这个推理，最终得到完整数值的升序。

例如 `12 11` 经个位排序变成 `11 12`。二者十位都为 1，下一轮必须保留这个顺序；如果同桶内任意交换，又变回 `12 11`，排序就失败了。

这里的稳定性既保证 LSD 的正确性，也保证完整关键字相等的记录保持原相对次序。

## 4. C 语言实现：用计数确定桶内位置

下面的函数需要包含 `<stddef.h>`，以使用 `size_t`。不必为十个桶各建一个数组。可以用计数数组记录当前位的分布，再算出各桶在统一辅助数组中的位置：

- 先统计当前位数字 d 出现了多少次。
- 计算前缀和，使 `count[d]` 表示当前位数字不大于 d 的元素总数。
- 从后向前遍历输入，把元素写入 `buffer[--count[d]]`。
- 把辅助数组复制回输入数组，供下一轮使用。

```c
/* 非负整数升序；array 与 buffer 不重叠，均可容纳 n 个元素。 */
void RadixSort(unsigned int array[], unsigned int buffer[], size_t n)
{
    if (n < 2) {
        return;
    }

    unsigned int max = array[0];
    for (size_t i = 1; i < n; ++i) {
        if (array[i] > max) {
            max = array[i];
        }
    }

    unsigned int exp = 1;
    for (;;) {
        size_t count[10] = {0};

        /* 统计当前位的数字出现次数。 */
        for (size_t i = 0; i < n; ++i) {
            unsigned int digit = (array[i] / exp) % 10U;
            ++count[digit];
        }
        /* 前缀和：count[d] 表示数字不大于 d 的元素总数。 */
        for (size_t d = 1; d < 10; ++d) {
            count[d] += count[d - 1];
        }
        /* 从后向前放置，保持相同数字元素的原相对顺序。 */
        for (size_t i = n; i > 0; --i) {
            unsigned int digit = (array[i - 1] / exp) % 10U;
            buffer[--count[digit]] = array[i - 1];
        }
        for (size_t i = 0; i < n; ++i) {
            array[i] = buffer[i];
        }

        /* 先判断是否还有更高位，再乘 10，避免位权溢出。 */
        if (max / exp < 10U) {
            break;
        }
        exp *= 10U;
    }
}
```

### 为什么从后向前填入

前缀和给出的是每个桶的结束位置，`--count[digit]` 每次取出桶中最靠后的一个空位。倒序处理输入，后出现的元素先占后面的格子，先出现的元素随后占前面的格子，所以同桶内的原次序不变。

如果仍然使用这套结束位置，却从前向后读取输入，就会颠倒同桶元素，破坏稳定性。也可以设计“从前向后读、用桶起始位置递增写入”的稳定实现，但不能混用两套位置规则。

### 辅助数组与边界

调用者为 array 和 buffer 各提供至少 n 个位置，二者不能重叠；buffer 的初始内容没有要求。完整程序只创建一次 buffer，各轮复用。n 为 0 或 1 时直接返回。

`count` 每一轮都重新清零，因为上一轮结束时它已经被前缀和和放置操作修改，不能当成下一轮的频次表继续使用。数组元素是整数，但 count 保存的是数量和下标，因此使用 `size_t`。

### 如何避免位权溢出

位权 exp 依次取 1、10、100……，当前位为 `(value / exp) % 10`。若直接在循环中不断乘 10，最大整数附近可能发生溢出，后续甚至可能出现除以 0。

本实现先判断 `max / exp < 10`：成立时，当前位已经是最高位，立即结束；否则还有更高位，此时 `exp * 10 <= max`，乘法仍在 `unsigned int` 的范围内。最大值为 0 时，也会正常完成一轮个位处理并结束。

## 5. 时间、空间与适用范围

设元素个数为 n，基数为 r，最大关键字的位数为 d：

- 每轮统计和放置、复制元素需要 O(n)，处理计数数组需要 O(r)。
- 共处理 d 轮，时间复杂度为 **O(d(n+r))**。
- 辅助数组需要 O(n)，计数数组需要 O(r)，额外空间为 **O(n+r)**。

本篇 r 固定为 10，因此可写成 O(dn) 时间和 O(n) 额外空间。实现不会因输入原本有序就跳过轮次；位数相同的输入，最好、平均、最坏的渐近开销相同。不能忽略 d，笼统说“基数排序对任意关键字都是 O(n)”。

基数排序不依靠任意两个完整关键字之间的大小比较来排序，因此不受比较排序模型中 Ω(n log n) 比较次数下界的直接约束；代价转移到了位数、基数和辅助空间上。

本实现支持 0 到 `UINT_MAX` 范围的非负整数。**它不直接支持负数**：把负数强制转成无符号整数，会改变按原有符号数值排序的含义。若处理有符号整数、字符串或复合关键字，需要另行定义分位和顺序规则。

相较于前面的排序，基数排序适合关键字可以按位拆分、位数可控，并且能提供辅助空间的场景。若关键字位数很多，或不容易拆成有限范围的“位”，就不能只依据线性形式的公式判断它更合适。

## 6. 编译与运行

完整程序见 [radix_sort.c](src/sort/radix_sort.c)。已安装 GCC 时，可在源文件目录运行：

```sh
gcc -std=c11 -Wall -Wextra -pedantic radix_sort.c -o radix_sort
./radix_sort
```

输出：

```text
7 7 12 23 53 80 105
```

可以对照第一轮分桶表，手推 53 和 23 在辅助数组中的位置，再检查为什么下一轮必须读取本轮收集后的序列。
