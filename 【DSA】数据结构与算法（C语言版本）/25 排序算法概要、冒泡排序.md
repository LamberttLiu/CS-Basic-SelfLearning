# [83] 排序基本概念

排序要解决的是：把一组记录按指定的关键字重新排列。比如把学生记录按成绩升序排列，比较的是成绩，移动的却是包含姓名、学号等信息的整条记录。

本篇先说明判断排序算法时需要关注的几个概念，再用冒泡排序演示“比较、交换、缩小未排序区间”的过程。代码按升序排列整数。

## 1. 排序的输入与输出

输入是含有 n 条记录的序列；输出仍然包含这些记录，只改变排列顺序，使关键字满足：

$$k_1 \le k_2 \le \cdots \le k_n$$

除了检查结果是否有序，还要确认记录没有丢失、重复或被修改。空序列和只有一条记录的序列不需要排序。

## 2. 算法的稳定性

**稳定排序会保留相同关键字记录的原始相对次序。**

例如按成绩升序排列以下记录：

| 输入顺序 | 姓名 | 成绩 |
| --- | --- | --- |
| 1 | 小林 | 80 |
| 2 | 小陈 | 60 |
| 3 | 小周 | 80 |

稳定排序的结果是“小陈、小林、小周”：小林和小周同为 80 分，排序后小林仍在小周前面。如果结果变成“小陈、小周、小林”，虽然成绩仍然有序，但两条 80 分记录的相对次序变了。

稳定性尤其适合多关键字排序。例如先按学号排序，再用稳定算法按成绩排序，同分学生就仍按学号排列。它不是衡量算法好坏的唯一标准，还要考虑时间、额外空间和数据特点。

## 3. 内部排序与外部排序

| 类别 | 数据条件 | 主要关注点 |
| --- | --- | --- |
| 内部排序 | 待排数据可以全部放入内存 | 比较与移动次数、额外空间、稳定性 |
| 外部排序 | 待排数据不能全部放入内存，需要分批处理 | 除计算开销外，还要关注外存读写次数和数据组织方式 |

插入、选择、冒泡、希尔、快速、堆、归并和基数排序是后续文章讨论的主要方法；具体复杂度和适用条件在各篇中说明。外部排序通常会先在内存中生成有序段，再分批归并。

描述空间开销时，**原地排序（in-place）通常指只使用常数级额外空间**。它仍然需要临时变量，并不意味着完全不使用额外内存。分析递归算法时，也要计入调用栈。

# [88] 冒泡排序

## 1. 算法思想

冒泡排序反复比较相邻元素，遇到逆序就交换。[NIST 的算法词典](https://xlinux.nist.gov/dads/HTML/bubblesort.html)给出了这种定义，并说明可以在每趟后缩小比较范围。

冒泡可以有两种方向：

- 从左向右比较，把较大元素逐步移到右侧，每趟确定一个最大值。
- 从右向左比较，把较小元素逐步移到左侧，每趟确定一个最小值。

**下文只使用第二种方向。** 每趟开始时，左侧已有若干元素处于最终位置；我们只处理剩下的区间。

## 2. 手推一趟排序

以 `5 1 4 2 8` 为例，第一趟从最右侧开始：

| 步骤 | 比较的相邻元素 | 操作 | 当前序列 |
| --- | --- | --- | --- |
| 1 | 2 和 8 | 已有序，不交换 | 5 1 4 2 8 |
| 2 | 4 和 2 | 逆序，交换 | 5 1 2 4 8 |
| 3 | 1 和 2 | 已有序，不交换 | 5 1 2 4 8 |
| 4 | 5 和 1 | 逆序，交换 | **1** 5 2 4 8 |

从右向左扫描时，每次比较都会把两者中较小的元素留在左边，继续参与下一次比较。因此，一趟结束后，未排序区间的最小值一定到达了区间最左端。

后续各趟如下：

| 趟数 | 本趟处理范围（下标） | 趟后序列 | 是否交换 |
| --- | --- | --- | --- |
| 1 | 0—4 | **1** 5 2 4 8 | 是 |
| 2 | 1—4 | **1 2** 5 4 8 | 是 |
| 3 | 2—4 | **1 2 4** 5 8 | 是 |
| 4 | 3—4 | 1 2 4 5 8 | 否，结束 |

第三趟后数组恰好已经有序，但程序不会仅凭这一点自动知道。第四趟没有发生交换，才触发提前结束。如果所有相邻元素都没有逆序，那么整个待排区间就是有序的。

n 个元素**最多需要 n−1 趟**；最后一个元素无需再单独安排一趟。通过“本趟是否交换”的标记，也可能更早结束。

## 3. C 语言实现

下面的程序使用 C11，包含完整的排序函数与调用示例。与上面的手推方向一致：`i` 是本趟要确定的位置，`j` 从右向左扫描。进入第 `i` 趟时，下标小于 `i` 的位置已经确定，不再参与比较。

```c
#include <stdbool.h>
#include <stdio.h>

/* 升序排序；n >= 0，n >= 2 时 array 指向至少 n 个可写元素。 */
void BubbleSort(int array[], int n)
{
    if (n < 2) {
        return;
    }

    for (int i = 0; i < n - 1; ++i) {
        bool exchanged = false;

        /* 从右向左比较，将未排序区间的最小值移到 array[i]。 */
        for (int j = n - 1; j > i; --j) {
            if (array[j - 1] > array[j]) {
                int temp = array[j - 1];
                array[j - 1] = array[j];
                array[j] = temp;
                exchanged = true;
            }
        }

        if (!exchanged) {
            break;
        }
    }
}

int main(void)
{
    int array[] = {5, 1, 4, 2, 8};
    int n = (int)(sizeof array / sizeof array[0]);

    BubbleSort(array, n);
    for (int i = 0; i < n; ++i) {
        printf("%s%d", i == 0 ? "" : " ", array[i]);
    }
    putchar('\n');
    return 0;
}
```

输出：

```text
1 2 4 5 8
```

完整源文件见 [bubble_sort.c](src/sort/bubble_sort.c)。可在已安装 GCC 的环境中进入源文件所在目录编译运行：

```sh
gcc -std=c11 -Wall -Wextra -pedantic bubble_sort.c -o bubble_sort
./bubble_sort
```

函数不检查指针是否有效：`n` 必须非负，`n >= 2` 时需要传入至少有 n 个可写元素的数组。`n` 为 0 或 1 时直接返回。

## 4. 时间与空间开销

以下分析针对上面带有提前结束标记的实现。

| 输入情况 | 比较与交换 | 时间复杂度 |
| --- | --- | --- |
| 已经升序，n ≥ 2 | 第一趟比较 n−1 次，交换 0 次，随后结束 | O(n) |
| 元素互异且严格逆序 | 每次比较都交换，完成 n−1 趟 | O(n²) |
| 元素互异的所有排列等概率出现 | 平均需要二次量级的比较与交换 | O(n²) |

严格逆序时，比较次数和交换次数均为：

$$ (n-1)+(n-2)+\cdots+1=\frac{n(n-1)}{2} $$

无论输入多长，程序都只需要循环变量、交换标记和一个临时整数，因此额外空间复杂度为 **O(1)**。交换两个数组元素时，代码会进行三次整数赋值，不需要额外数组。

## 5. 为什么冒泡排序稳定

代码只在 `array[j - 1] > array[j]` 时交换，关键字相等时不交换。相同关键字的两条记录若要改变相对顺序，必须在某次相邻交换中越过彼此；这里不会发生这种交换，因此算法稳定。

如果把条件改为 `>=`，相等元素也会交换，就不能再保证稳定性。例如两个关键字相等的记录在第一趟就可能互换位置。

## 6. 适用范围与小结

冒泡排序的优势是过程直观、使用常数额外空间，并且容易说明稳定性和提前结束机制。其平均与最坏时间复杂度都是 O(n²)，不适合用来处理大规模的一般排序任务。

链表也可以通过相邻比较实现冒泡，但不能照搬数组下标代码。单链表通常沿 `next` 从前向后扫描；交换记录数据还是调整结点链接，也需要另行选择实现方式。
